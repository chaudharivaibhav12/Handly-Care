## Decision
Branch B finds objects class-agnostically: Viam's built-in point-cloud segmenter (`obstacles_pointcloud`,
service `anything-3d`) returns every blob above the table with its world position and measured size, and
Claude names each new blob from a crop of the color image. Graspability comes from the measured size
(gripper opening, height), not a fixed catalog. The shape finder (`shape-detector` + `objects-3d`) stays
configured as the fallback for colored blocks.

## Reason
Vaibhav wants the arm to pick up anything, not depend on color or a fixed object list. The shape finder's own
README says it detects only colored squares and rectangles (labels `<shape>-<color>`, not configurable),
so the cup and the black marker are invisible to it (LOG 12:35). Depth segmentation needs no training and no
labels, and makes the demo's refusal a measured one ("31 cm wide, my gripper opens ~8 cm").
Cost: ~1.5–2 h of code, built and tested in sim while the services are configured.

## Evidence
EXP-001: movement is reliable (5/5, honest grab sensor), so Branch B is unblocked and the pick-up side
does not need to change. No vision experiment exists yet. This choice rests on the README and design
reasoning, so EXP-002 must test it on the real camera.

## What would make us revisit it
- EXP-002: the segmenter doesn't separate the objects steadily (each seen, ±10 mm over 3 runs), or merges an
  object with the tray. Then fall back to the shape finder with colored objects (or color detectors).
- Claude naming is slow (>8 s) or wrong on 2+ of 4 objects → use size/color fallback names.
- 4 PM checkpoint (train-or-color) not reached with M2 passing.
